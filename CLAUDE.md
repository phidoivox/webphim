## Project Overview

WebPhim — a Vietnamese movie streaming web application, currently at early-stage scaffolding. Two independent apps in one repo:

- **Laravel 13 API backend** (repo root, PHP 8.3, MySQL) — Eloquent schema + models for the full movie domain exist; routing is minimal (only a `/api/status` health endpoint). No controllers or business logic yet.
- **Next.js 16 frontend** (`frontend/`, React 19, TypeScript, Tailwind 4, App Router) — currently a connection-test page that probes the Laravel API from the browser.

Local dev environment is **Windows + Laragon** (Apache/MySQL). `.mise.toml` pins node 24.18.1 and pnpm 11.20.0. UI copy and code comments mix Vietnamese and English — keep this style.

## Commands

Backend (run from repo root):

```bash
composer dev                 # full dev loop: artisan serve + queue:listen + pail logs + vite, concurrently
php artisan serve            # API server alone (http://127.0.0.1:8000)
composer test                # php artisan test (PHPUnit; sqlite :memory:, see phpunit.xml)
php artisan test --filter=TestName   # single test
vendor/bin/pint              # PHP code style (Laravel Pint)
composer setup               # fresh install: deps, .env, app key, migrate, build assets
```

Frontend (run in `frontend/` or with `--prefix`):

```bash
pnpm dev                     # Next.js dev server (http://localhost:3000)
pnpm lint                    # ESLint (eslint-config-next core-web-vitals + typescript)
pnpm build                   # Next.js production build
```

Package manager split: **npm** for root Laravel/Vite asset builds (root `.npmrc` sets `ignore-scripts=true`), **pnpm** for the `frontend/` app (pnpm workspace, `packageManager: pnpm@11.20.0`). `composer dev` does NOT start the Next.js dev server — run those separately. `mise run frontend:dev` / `frontend:build` / `frontend:install` are equivalents for the frontend tasks.

## Architecture

### Backend (Laravel, API-only)

- **Schema is recent (Aug 2026) and authoritative** — models mirror migrations in `database/migrations/`. Domain: `Movie` (self-referential `parent_id` for series/seasons; `SoftDeletes`; MySQL fulltext index on name/origin_name for search), `Genre`, `Country`, `Tag`, `Person` (many-to-many `movie_person` pivot with `role` — the model exposes scoped `actors()` / `directors()` relations), `Episode` → `EpisodeServer` (one movie = many episodes, each with multiple streaming servers), `Comment` (+ comment likes), `Rating`, `Bookmark`, `WatchHistory`, `Collection` (many-to-many `collection_movie`), `EpisodeReport`, `MovieViewLog`, `AuditLog`, `User`.
- **Users** are extended via migration: `role` (`user` default), `subscription_type` (`free` default), `subscription_expires_at`, `avatar_url`, `is_active` — a subscription/role model is anticipated.
- `Movie` carries denormalized counters (`view_count`, `comment_count`, `rating_avg`, `rating_count`) and sync fields (`tmdb_id`, `imdb_id`, `source_url`, `last_synced_at`) — external data source (TMDb/IMDb + a streaming source) is planned; there is no sync code yet.
- Models use the new-style `casts()` method (Laravel 11+ convention). Eloquent relation methods are the primary documentation of the domain.
- Routes: `routes/api.php` (currently only `GET /api/status` returning a JSON health check) and `routes/web.php` (default `welcome` Blade view, not the real UI).
- Tests are PHPUnit example stubs only (`tests/Feature`, `tests/Unit`); phpunit.xml runs against in-memory SQLite while local dev uses MySQL DB `webphim`.

### Frontend (`frontend/`, Next.js 16 App Router)

- **`frontend/AGENTS.md` warns: this is NOT the Next.js from training data — Next 16.3 has breaking changes.** Read the relevant guide in `node_modules/next/dist/docs/` before writing frontend code, and heed deprecation notices. The file is regenerated by `next dev` — don't fight it.
- App lives in `frontend/src/app/` (App Router, `"use client"` pages).
- Backend discovery: `page.tsx` builds `POSSIBLE_API_URLS` from `NEXT_PUBLIC_API_URL` (default `http://webphim.test/api`) and falls back to probing `http://localhost/webphim/public/api`, `http://127.0.0.1:8000/api`, `http://localhost:8000/api` — the Laragon domain (`webphim.test`) and `php artisan serve` ports are both expected to work. When adding real API calls, keep this multi-URL fallback pattern in mind or replace it deliberately.
